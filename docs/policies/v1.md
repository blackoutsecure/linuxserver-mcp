# Repository policy v1

Version: **1.0.0**. The canonical executable catalogue is
[policy/v1.ts](../../packages/mcp-server/src/core/policy/v1.ts).
The same rules run through CLI, Action, and both MCP transports.

## Findings and authority

Every finding has a rule ID/version, severity, confidence, classification,
evidence path/line, source links, and manual remediation. Cross-file rules
include evidence from both sides. Evidence contains only derived, relevant
values, not raw secret-bearing lines. No score implies certification.

`required` describes a parser/repository invariant, not blanket LinuxServer
endorsement. `contextual` applies only when its documented conditions hold.
`capability` requires explicit support metadata. `advisory` is not an official
LinuxServer requirement. Evidence kinds distinguish documentation, observed
conventions, general security, project recommendations, and heuristics.

## Configuration and suppression

`recommended` runs all implemented rules. `linuxserver` excludes general
security/supply-chain advice. `security` selects that advice only.

Repository configuration is versioned and strict. Disabled rules and
diff-irrelevant rules are visible under skippedRules. Changing the configuration
file reconsiders all selected rules, not only one file type.

Suppressions require exact evidence paths and a reason. They remain visible in
JSON and SARIF and do not cross failure thresholds. Source-parse rules cannot
be suppressed. Unknown rule IDs are configuration errors.

```yaml
version: 1
suppressions:
  - rule_id: LSIO-CI-PORT-001
    paths: [jenkins-vars.yml]
    reason: CI intentionally tests an internal-only health endpoint.
```

## Deliberate limits

The engine recognizes a bounded set of source files, not all Docker/Compose or
template language semantics. It does not execute Jinja, shell, build tools, or
services. Dynamic ports/unknown architecture expressions do not produce
definitive mismatch findings. The default Dockerfile architecture is not
guessed. Multi-stage ports are checked only in the final stage.

No universal `/config`, PUID/PGID, healthcheck, read-only, or non-root requirement
is invented. General recommendations do not become LinuxServer policy.
Missing SBOMs, attestations, or checksums are not reported as violations without
an implemented, sourced applicability model.
